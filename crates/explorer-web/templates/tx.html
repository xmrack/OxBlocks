What do these fields mean?
Version / RingCT type
RingCT hides amounts behind commitments. Type 0 means no RingCT: the transaction predates it, or is a coinbase, whose amount is public by construction. 1–2 are the original scheme, 3 and 4 use Bulletproofs, 5 adds CLSAG signatures, 6 uses Bulletproofs+. Later types are smaller and cheaper to verify, not more private.
Ring size
How many outputs each input could have spent — one real, the rest decoys, indistinguishable to an observer. Monero fixes this by consensus rather than letting senders choose, because an unusual ring size would itself stand out; it has been 16 since August 2022. A coinbase creates coins rather than spending them, so it has no ring.
Unlock time
A height or timestamp before which these outputs cannot be spent. 0 means no lock, which is the normal case. Every coinbase is locked for 60 blocks, so one shows its own height plus 60.
Payment ID
An optional identifier a sender attaches so a recipient can tell payments apart. The 16-character form is encrypted to the recipient and is what integrated addresses carry. The 64-character form is readable by anyone, marks the transaction as unusual, and is deprecated.

What am I looking at?
Key image
A value derived from the one real output being spent. It is unique to that output but reveals nothing about which one it is. The network refuses a second transaction carrying the same key image, which is how double spends are prevented without anyone learning what was spent.
Ring members
The listed outputs are the candidates for this input: one was really spent, the others are decoys pulled from the chain. Nothing here distinguishes them.
The age chart
How old each ring member was when it was spent. Decoys are drawn from a gamma distribution favouring recent outputs, because real spends usually are recent too — so a healthy ring leans left and the real output does not stand out by age. The buckets double in width because a linear axis would put nearly everything in the first one.

What am I looking at?
One-time key
Every output pays a fresh one-time address, derived by the sender from the recipient's published address and a random value only the sender knows. The recipient's actual address never appears on the chain, and two payments to the same person share nothing an observer can link. The recipient finds their own outputs by scanning with their view key.
{% if has_view_tags %}
View tag
One byte derived from the same shared secret as the one-time key. A scanning wallet can skip an output whose view tag does not match without doing the much more expensive full derivation, which made scanning several times faster when it arrived in 2022. It narrows an output to one bucket in 256 and reveals nothing further.
{% endif %}
Amount
hidden means RingCT is concealing the value: it is committed to on the chain but not published. A figure here instead means the amount is public — every coinbase, and any transaction predating RingCT.

Extra tx_extra

A free-form byte field on every transaction. By convention it carries the transaction public key the recipient needs to recognise their outputs, sometimes an encrypted payment ID, and on coinbases whatever tags a merge-mining or pool setup adds. monerod does not require it to parse, so some transactions carry bytes that decode to nothing.
