RingCT hides transaction amounts behind commitments. Type 0 means no RingCT: the transaction predates it, or is a coinbase, whose amount is public by construction. Types 1–2 are the original scheme with range proofs; 3 and 4 use Bulletproofs; 5 adds CLSAG signatures; 6 uses Bulletproofs+. Later types are smaller and cheaper to verify, not more private.

Ring size
{% if coinbase %}—{% else %}{{ ring_size }}{% endif %}
?

How many outputs each input could have spent, one of which is real and the rest decoys. An observer cannot tell them apart, so the ring is the anonymity set for that input. Monero fixes the ring size by consensus rather than letting senders choose — a transaction with an unusual ring size would stand out — and it has been 16 since August 2022. A coinbase creates coins rather than spending them, so it has no ring.

Unlock time
{{ unlock_time }}
?

A height or timestamp before which these outputs cannot be spent. 0 means no lock, which is the normal case. Every coinbase is locked for 60 blocks by consensus, so a coinbase shows its own height plus 60 here.

# One-time key
?

Every output pays a fresh one-time address, derived by the sender from the recipient's public address and a random value only the sender knows. The recipient's actual address never appears on the chain, and two payments to the same person share nothing an observer can link. The recipient finds their outputs by scanning with their view key.

 AmountView tag
?

One byte derived from the same shared secret as the one-time key. A wallet scanning the chain can skip an output whose view tag does not match without performing the much more expensive full derivation, which made scanning several times faster when it was introduced in 2022. It narrows an output to one bucket in 256 and reveals nothing else.
